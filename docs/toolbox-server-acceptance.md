# Toolbox subscription migration acceptance

## Local source-backed environment

Run `bun run server:dev` from the repository root. It starts a dedicated PostgreSQL container, the `sempre-server` source build under Cargo Watch, and the `server-ui` Vite server. The API listens on `127.0.0.1:8788`; Vite listens on `127.0.0.1:5174` and forwards `/api` to that API. This entry point does not run `sempre-client` or its proxy core.

When Vite is already running, `bun run server:dev --api-only` starts only the source API watcher with the same isolated database and port. It does not restart Vite.

On a fresh `toolbox` database, run `bun run server:dev --migrate` once before starting the API. For a new migration while Cargo Watch is already running, wait until it has compiled the changed server, then run `bun run server:dev --migrate-built`. That uses the just-built local binary without waiting on Cargo's build lock. Startup checks the expected schema and does not automatically migrate another database.

The `toolbox` database lives in Docker volume `sempre-toolbox-dev-postgres-data`, exposed only at `127.0.0.1:15433`. Its password is generated once in ignored `.cache/sempre-toolbox-dev/postgres-password`. The existing Docker server on port 8787 and its `sempre-local-server_postgres-data` volume are separate. The development script does not seed or reset data.

The container's registration policy comes from Toolbox `system_settings`, and sessions use the server's seven-day policy. `SEMPRE_ALLOW_REGISTRATION` and `SEMPRE_SESSION_DAYS` are obsolete for this service; Compose retains only `SEMPRE_ACCESS_LOG_RETENTION_DAYS` for access-log maintenance.

Stop the foreground `bun run server:dev` process with Ctrl-C. To stop only the development database, run `docker compose -p sempre-toolbox-dev -f scripts/server-dev.compose.yml stop postgres`. Do not use `down -v` for ordinary shutdown, because that would remove the development database.
