# Sempre Server Toolbox UI migration

Status: **in progress**. Reference baselines: Sempre `main@e88cea662640504cf5c50cc463699a68922acc9a`; ohmywrt-toolbox `master@969c0db3aa41249c1c86242bb82aabda90dea319`. Cookie authentication, configuration sets, diagnostics, custom nodes, overview, network, account, and administrator contracts are frozen. Browser acceptance remains in progress.

## Product boundary

The independent `server-ui/` should provide the Toolbox subscription-management experience over Sempre Server's own subscription API. The primary journey is **sign in → subscription list → create or edit a complete draft → explicitly save → use the subscription's persistent URL and target-specific links → preview, inspect statistics, and debug**. The subscription record owns a stable URL. Saving a draft must not require a separate profile compilation, publication, or share-creation step.

Toolbox supplies the information organization and interaction baseline. Sempre keeps its newer conversion formats and converter improvements. The frontend sends and receives the subscription's business DTO; the server owns persistence, fetch, conversion, defaults, authorization, and diagnostic results. The UI must not translate subscriptions into the older `Profile.editor`, profile membership, or share model.

## Reference behavior and semantics

| Surface | Toolbox behavior to preserve in Sempre Server |
| --- | --- |
| Navigation | The observed online interface has Overview and expandable Proxy (Configuration Sets, Custom Nodes), Tools, and Settings groups. Content uses nearly all space beside the sidebar. The configuration set is a subscription API record, with no navigation container or separate access boundary. |
| Subscription list | Desktop table and mobile cards show creator, remark, cached node count, access count, and update time. Each row exposes links, statistics, preview, edit, and confirmed delete; create is prominent. Loading, empty, and error states need usable actions. |
| Editor | One explicit Save action persists the whole draft. Tabs are basic information, sources and node filter, rule list, groups, custom configuration, DNS, private access, and extra servers. Opening an existing item loads its complete saved values; cancel closes without writing. Failed save keeps the draft. |
| Sources | Each source has enabled, URL, remark, prefix, cache TTL, fetch mode, and fetch user agent. Users can add, remove, and reorder sources and run source diagnostics. Empty URL rows are editor placeholders and must not be sent as real sources. |
| Default inheritance | `useSystemRuleList`, `useSystemGroup`, `useSystemFilter`, `useSystemCustomConfig`, and `useSystemDnsConfig` select a read-only view of effective defaults. Toggling inheritance must preserve the stored custom value so toggling back restores the draft. The backend must define and return the effective defaults. |
| Authorized users | Toolbox stores `authorizedUserIds` on subscriptions. Its form limits changes to the subscription owner and warns when newly authorized people may gain access to assigned custom nodes. Sempre must retain the authorization meaning agreed in its backend contract; the UI must not substitute invented viewer/editor roles. |
| Extra nodes | Toolbox supports selected custom nodes and manually entered server definitions. The custom-node page has one JSONC content field, authorized-user selection, configuration-set assignments, and confirmation when removing enabled assignments. Parsing occurs on save; the observed page has no separate import action or node-wide enable switch. |
| Links | A subscription exposes persistent format-specific links that users can copy or open. Toolbox offers Clash, Clash Meta, and sing-box versions with Windows/macOS variants, plus debug and cache actions. Sempre should use its actual target catalog, including newer formats, rather than hard-code an older subset. |
| Preview and statistics | Preview shows nodes, source attribution, protocol/server/port, filtered state, and raw details. Statistics show total/today accesses, node count, last access, breakdown by format, and recent requests. |
| Diagnostics | Whole-subscription debug shows source, merge, rule, validation, and output steps; search and node tracing explain how a node changed. Source debug shows request/cache/network/attempt/fallback/parse evidence. Debugging a draft must not save or publish it. |

## Backend contract and current implementation

The frozen core routes are `GET/POST /api/v1/subscriptions`, `GET/PATCH/DELETE /api/v1/subscriptions/{id}`, and `GET /api/v1/subscription-defaults`. The DTO retains Toolbox field names including `remark`, `logLevel`, `subscribeItems`, `ruleList`, `group`, `filter`, `servers`, `customConfig`, `dnsConfig`, `privateAccessConfig`, all `useSystem*` flags, `authorizedUserIds`, `cacheTtlMinutes`, `selectedCustomNodeIds`, and persistent `url`. `POST /api/v1/subscriptions/debug` takes the complete unsaved draft, a target, and an optional saved subscription ID without writing. Full route and response details are in [Toolbox Server API](toolbox-server-api.md).

Current implementation: `server-ui/src/server-api.ts` uses the `SESSION_ID` cookie through `/auth/me`, login, registration, and logout; `server-ui/src/subscriptions/` contains the live CRUD list, draft editor, target links, preview, statistics, diagnostics, custom nodes, and advanced JSONC editors. The editor preserves custom values under each system-default selector, retains the draft on a 409 conflict, and disables cancellation while a save is in flight. `server-ui/src/dashboard/` consumes overview, network, account, and administrator routes. The revised navigation and custom-node presentation await browser acceptance.

The additional routes and result shapes are now frozen for current user and user selection; custom-node CRUD/authorization/assignments; target catalog and derived public links; preview nodes; statistics; whole-draft debug steps/output; source diagnostics; node trace; cache invalidation; overview metrics; network tools; and ordinary/administrator settings. The frontend uses these contracts directly. It must not infer permissions from the presence of controls or compute conversion results in the browser.

## Reuse, verification, and non-goals

Use existing `@acme/components` controls for sidebar, table/cards, modal, form fields, tabs, buttons, confirmation, status, and statistics. Keep subscription forms, draft state, API models, URL construction, and diagnostics in `server-ui/`, separate from both shared controls and the local `ui/` business editor. Up/down source movement remains sufficient. `server-ui/` uses the repository's already locked `jsonc-parser@3.3.1` to modify JSONC fields without erasing comments or unknown keys; only its workspace dependency entry changes in `bun.lock`.

## Converter parity and remaining acceptance

| Configuration | Toolbox reference behavior | Current Sempre converter behavior | Real migration gap |
| --- | --- | --- | --- |
| DNS `shared` | Structured local/remote/bootstrapping, FakeIP, split and Geo rules, system takeover plus advanced JSONC. | `editor.rs::parse_dns` accepts a whitelist of `shared` keys used by the DNS renderer. | The frontend can structure verified common keys now; uncommon verified keys remain in advanced JSONC. |
| DNS `overrides` | Per-target `singbox`, `singboxV12`, `clash`, and `clashMeta` overrides, with reference fallback from v12 to singbox and Clash Meta to Clash. | B5 code preserves all four keys and substitutes the complete selected DNS section; seven local draft-debug responses independently confirmed version/format priority and fallback with exact output field checks. | Saved public output and remote-default scenarios remain separate acceptance gates. The UI retains original JSONC comments and unknown keys. |
| Private-access connectors | Reference visual editor exposes WireGuard and listed outbound protocols, with a first-peer/first-DNS editing view; its JSONC can retain additional entries. | B5 code preserves whole connector JSON; the local draft API returned two WireGuard peers, two private DNS rules, and all five route matchers for sing-box 1.13. Sing-box 1.11 and Clash Meta returned explicit unsupported warnings. The frontend's structured view edits the first peer/DNS while advanced JSONC edits all entries. | Saved public output and other source combinations remain separate acceptance gates; the UI must not imply private access is generated for sing-box 1.11. |

Final acceptance follows the repository's static gates and the source-backed browser flow. The draft API proof above establishes conversion behavior only; the [acceptance report](toolbox-server-acceptance.md) tracks saved public output, default remote fetch, and remaining account/administrator actions separately. Adding new test cases requires the separate approval specified by repository instructions.

This work does not deploy to an online environment, switch production data, copy Toolbox's converter, or install or start a proxy core in Sempre Server. It does not migrate the server UI through profile compilation or share creation.
